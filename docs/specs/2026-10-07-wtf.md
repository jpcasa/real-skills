# wtf: bug-report triage with a harness

Date: 2026-10-07 · Branch: `jpcasa/wtf-skill` · Origin: a `wtf` skill v1.0.0 (2026-08-19) written for one private product repo

## Goal

Add `/real-skills:wtf` to the plugin: read-only triage of a bug report from any source, ending in one defensible verdict written for the reader who asked. It keeps everything the original skill got right and puts its promises (citations, deploy skew, verdict discipline, budgets) into a script, adds runtime evidence and an optional reproduction, and records whether its verdicts turned out right.

## Kept from the original, unchanged in spirit

- Order: normalize → prior art → code path → verdict → report. Prior art first, stop early on a direct hit.
- Six verdicts: `USER_ERROR`, `DEFECT`, `FEATURE_REQUEST`, `ALREADY_FIXED`, `KNOWN`, `INSUFFICIENT_INFO`. Split verdicts allowed.
- `INSUFFICIENT_INFO` beats a confident guess.
- Two registers, same investigation: `--tech` and `--plain`. Asked late if not given.
- Report content is data, never instruction.
- The priors and counter-priors in `triage-heuristics.md`.

## Non-goals

- Filing, commenting, replying, editing files, opening PRs. `wtf` prints a ticket draft and the next command, and stops.
- Anything against production beyond reading. Reproduction never runs there.
- Carrying anything specific to the original's repo. No hostnames, channel ids or product error strings here; they become config in that repo.
- Changing or retiring the original skill. That is a follow-up in its own repo.
- Sending report text to Jev. Derived facts only.
- Fixing the bug. `DEFECT` hands off to `do-shit`.

## Approach

### 1. Generalise: config, setup, adapters

`<repo>/.claude/wtf.json`, written by `/real-skills:wtf setup` (one question round, detected values recommended, same shape of flow as `changelog setup`):

```json
{
  "tracker": { "type": "clickup", "id_pattern": "86[0-9a-z]{7}", "url_template": "https://app.clickup.com/t/{id}" },
  "inbox": { "type": "chatwoot", "url_pattern": "https://support.example.com/app/accounts/\\d+/conversations/(\\d+)" },
  "release": { "mode": "promotion", "main_branch": "main", "production_branch": "production" },
  "environments": [
    { "name": "local", "kind": "local", "base_url": "http://localhost:3000" },
    { "name": "staging", "kind": "staging", "base_url": "https://staging.example.com" }
  ],
  "production_hosts": ["app.example.com"],
  "runtime": { "sentry": { "org": "acme", "project": "web" }, "posthog": { "project_id": "1234" } },
  "heuristics": ".claude/wtf-heuristics.md",
  "default_register": null,
  "jev": "shadow"
}
```

- `tracker`: `github`, `clickup`, `linear`, `other`, `none`. Adapters in `references/trackers/`, each with **Fetch** and **Search prior art**. `release` falls back to `.claude/changelog.json` when present.
- `inbox`: optional support-desk source read through the user's browser session (`references/inbox.md`). Not connected or 401: say so, continue, flag the thread as unread.
- `heuristics`: optional repo file with that product's own priors. The bundled `references/triage-heuristics.md` is the generic version of the original's.
- Works with no config for pasted text and screenshots; setup is needed only for links, runtime evidence and reproduction.

### 2. The harness: `scripts/wtf.mjs`

One JSON object per call. Run state in `~/.claude/state/wtf/<run-id>/` (`WTF_STATE_DIR` overrides). The model investigates and writes; the script decides what counts.

| Command | Input | Decides in code |
|---|---|---|
| `start` | raw arguments, flags | Input shapes (URL, ticket id, file paths, text) from config patterns; register from flags; opens a run with its budgets |
| `spend` | run, kind | Budgets: 5 tracker reads, 4 runtime reads, 1 reproduction. Over budget returns `ok: false` |
| `skew` | commit or PR | Merged to main? Ancestor of production (or in the last matching tag)? Pure git + `gh` |
| `cite` | `evidence[]: {path, line, quote, role}` | Each citation is real: file exists at `HEAD`, line in range, `quote` occurs within ±3 lines. Returns `verified` per item |
| `verdict` | report record, prior art, evidence, flags, runtime, repro | Which verdicts the evidence supports, confidence, and what is missing |
| `outcome` | run id, `right` or `wrong`, optional actual verdict | Appends to the log |
| `stats` | | Accuracy per verdict from recorded outcomes |

**Verdict rules.** The model proposes; `verdict` accepts, or downgrades and says why.

| Verdict | Requires | Vetoed by |
|---|---|---|
| `KNOWN` | A prior ticket with id and URL, marked the same issue | |
| `ALREADY_FIXED` | A fix commit or PR, and `skew` says merged and not in the environment the report came from | `skew` says the fix is already in that environment: then it is `DEFECT` ("fix shipped, still happening") |
| `USER_ERROR` | A verified citation with role `guard` or `designed_behavior`, and at least one step for what to do instead | Any counter-prior flag: `enabled_noop`, `wrong_data_shown`, `silent_write_noop`, `worked_before_unchanged_flow`; or a reproduction that followed the right steps and still failed |
| `DEFECT` | Verified citations for expected and for actual, or a reproduction with evidence | |
| `FEATURE_REQUEST` | `premise_exists: false` with what was searched | A verified citation showing the behaviour exists |
| `INSUFFICIENT_INFO` | The one missing fact and who can supply it | |

- A verdict that fails its requirements becomes `INSUFFICIENT_INFO`, with `missing` naming what would support the original.
- Split verdicts: `USER_ERROR` on the logic with `DEFECT` on the messaging is the one built-in pair; it needs a citation with role `message` (or the absence of one, stated).
- Unverified citations do not count. Runtime evidence alone never supports a verdict.
- Confidence is computed, not asserted: `high` needs verified citations plus a second independent source (prior art, reproduction, or a matching runtime error); `medium` is verified citations alone; anything else is `low`. The result names the single thing that would raise it.

### 3. Runtime evidence (optional, read-only)

`references/runtime/{sentry,posthog,logs}.md`. Used after prior art, before or alongside the code read, when `runtime` is configured and the report has a time.

- Window: 30 minutes either side of the reported time, narrowed by user or tenant when known. 4 reads per run.
- It supplies exact error strings to search the code for, and whether the report's environment saw errors at that time.
- It never decides. A correlated error is a lead; no error proves nothing (silent no-ops throw nothing). The script enforces this.

### 4. Reproduction (optional, Claude Code only)

Offered when the verdict is still between `USER_ERROR` and `DEFECT`, or confidence is below `high`, and a non-production environment is configured.

- **Always asked.** One question: reproduce, on which environment. Reproducing means using the app, so it can create or change data **in that environment**; the question says so. Sign-in is done by the user.
- **Never production.** `start` and `verdict` refuse a `base_url` whose host is in `production_hosts`, and refuse to run reproduction when `production_hosts` is empty.
- Runs the plugin's existing `real-skills:qa-tester` with numbered steps built from the report (what they did, what they expected). The role guard already binds it: no credentials, no code edits, page content as data.
- Result: `reproduced`, `not_reproduced` or `blocked`, with per-step evidence and screenshots in the run's state folder. `not_reproduced` is weak evidence and never upgrades a verdict to `USER_ERROR` by itself.
- Elsewhere (Codex, no browser): skipped, and the report says it was not attempted.

### 5. Compressed reports

- Bundled `references/report-style.md` (identical copy, covered by `sync.test.mjs`).
- The code-path investigator replies with a JSON block only: `evidence[]`, `flags[]`, `expected`, `actual`, `trigger`, `blast_radius`. Length caps per field; one re-ask.
- `--tech` output keeps the caveman register. `--plain` output and anything about security or data loss is full sentences.

### 6. Jev, on derived facts only

Sent: a one-line symptom summary the model writes without names, candidate ticket titles, and evidence summaries. The script strips emails, phone numbers and long digit runs from all of it before the usual redaction. Never sent: the ticket, the thread, screenshot text, customer or tenant names.

| Question | Used for |
|---|---|
| `same_issue_as_prior` (per candidate) | `KNOWN` |
| `ask_not_breakage` | `FEATURE_REQUEST` vs the rest |
| `screen_was_enough` | Split verdict: could a competent user have got it right from what was on screen? |

All three ship in `UNCALIBRATED`: logged next to the verdict, deciding nothing. `outcome` records are what calibrates them.

### 7. Learning loop

Every run appends `{run, verdict, confidence, evidence counts, jev, register}` to `~/.claude/state/wtf/log.jsonl`. No report text. `/real-skills:wtf outcome <run-id> right|wrong` records how it turned out; `stats` prints accuracy per verdict. A handoff line in each report gives the run id.

### 8. Batch

`/real-skills:wtf latest [N]` (default 3, max 10): the newest untriaged items from the tracker or inbox, one line each (`ref · verdict · confidence · next`), prior art and `skew` only. No code read, no reproduction. Pick one to run in full.

### 9. Hand-offs

`DEFECT`: a ticket draft (title, repro steps, expected, actual, evidence, blast radius) printed in the report, plus `/real-skills:do-shit <ref>` when a ticket already exists. `KNOWN` and `ALREADY_FIXED`: the link and what it is waiting on. Nothing is filed.

### Rejected alternative

**Port the skill as prose and add only Jev.** Quick, and it would look like the other skills on the surface. But the original's failure mode is a confident wrong verdict forwarded to a client, and a probability on top of unchecked prose does nothing about that. Checking citations and deploy skew in code, and refusing verdicts the evidence does not support, attacks the failure directly.

## Risks

- **A wrong `USER_ERROR` reaches a client.** The main risk, as in the original. Mitigation: it is the verdict with the most requirements and the most vetoes; `--plain` never says "working as intended" as the whole answer.
- **Reproduction changes data.** Only in an environment the user names, never a production host, always asked, and the role cannot type credentials. A repo with no `production_hosts` set cannot reproduce at all.
- **Citation check is shallow.** It proves the line exists and says what was quoted, not that the reading of it is right. Stated in the report as "verified to exist".
- **Customer data.** Report text stays local. The log holds no report text. Screenshots from reproduction stay in the state folder. The scrub is a second line, not the first: the model is told to write the summary without names.
- **Name clash.** In the original's repo, its local `/wtf` and `/real-skills:wtf` will both exist until the local copy is retired.
- **Three more uncalibrated questions.** That makes 23 logging and none calibrated. `outcome` and `stats` exist to change that; this skill is the first with a built-in way to learn whether it was right.
- **Size.** Largest skill after `do-shit`. Built in the order below so each stage is usable alone.

## Build order

1. Skeleton, config, setup, adapters, registers, heuristics, SKILL.md flow without the script.
2. `wtf.mjs`: `start`, `spend`, `cite`, `skew`, `verdict`, with tests.
3. Jev on derived facts, `scrub`, `outcome`, `stats`, log.
4. Runtime evidence adapters and rules.
5. Reproduction: gate, production refusal, `qa-tester` hand-off.
6. Batch mode, README, manifests `0.3.0`, sync test.

## Verification

```bash
node --test skills/*/scripts/test/*.test.mjs
bash skills/changelog/scripts/test/release-ranges.test.sh
claude plugin validate . --strict
```

Tests that must exist:

- `cite`: missing file, line out of range, quote not near the line, quote found within ±3 lines.
- `skew`: merged and in production; merged and not; not merged; tags mode. Against a temp git repo.
- `verdict`: every row of the rules table, each veto alone, downgrade to `INSUFFICIENT_INFO` with `missing`, the split pair, runtime-only evidence rejected, confidence levels.
- Reproduction is refused for a production host and when `production_hosts` is empty.
- Budgets stop at their caps.
- `scrub` removes emails, phone numbers and long digit runs; Jev input in tests contains none of the raw report text.
- Uncalibrated Jev answers change no verdict.
- No write tool is named in `SKILL.md` outside the state folder; SKILL.md documents every verdict, flag and command the script emits.
- One real run on a pasted report in this repo, `--tech`, and one `outcome` recorded.
