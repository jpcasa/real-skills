# solve-merge-conflicts Plan

Spec: `docs/specs/2026-10-12-solve-merge-conflicts.md`
Goal: `/real-skills:solve-merge-conflicts` resolves a conflicted pull request in its own worktree, with a script that writes every resolution, checks every claim, runs the repo's checks and makes the one push.
Verify: `node --test skills/*/scripts/test/*.test.mjs && bash skills/changelog/scripts/test/release-ranges.test.sh && claude plugin validate . --strict`
Constraints:
- Node 20+, git 2.38+ (`merge-tree --write-tree`, `merge-file --zdiff3`), `gh`, `jq`. No dependencies.
- Every command prints one JSON object. Sides are `pr` and `base`, never ours/theirs.
- No force flag on any push. `--force` appears only on `git worktree remove`.
- The merge commit is built with `commit-tree`: HEAD of the worktree never moves, a second `check` recomputes it.
- Config is read from the user's checkout, never from the pull request's tree.
- `jev.mjs`, `redact.jq`, `calibration.mjs`, `glob.mjs`, `report-style.md` are copies; `sync.test.mjs` pins them.
